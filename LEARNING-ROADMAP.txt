PORTFOLIO LEARNING ROADMAP
==========================

Here's a set of features to build in order. Each one teaches one new React or
TypeScript idea, and each points to an existing file you can copy the pattern
from. Do them one at a time and run "npm run dev" to see each change.


LEVEL 1: EDITING WHAT EXISTS (JSX basics)
-----------------------------------------

1. Make it yours
   - Write your real intro in About.tsx and your real skills in Skills.tsx.
   - Change <title>my-portfolio</title> in index.html to your name.
   Learn: how JSX turns into what you see on the page.

2. Add a "Download CV" button to the Hero
   - Put a cv.pdf file in the public/ folder.
   - In Hero.tsx, add:
       <a href="/cv.pdf" download className="button">Download CV</a>
   Learn: files in public/ are served as-is, and attributes work like normal HTML.

3. Add social links to the Footer
   - Make an array like:
       const socials = [{ label: 'GitHub', url: '...' }, ...]
     and render it with .map().
   Copy from: Navbar.tsx (the "links" array).
   Learn: lists and the "key" prop.


LEVEL 2: DATA AND TYPES (TypeScript basics)
-------------------------------------------

4. Move skills into a data file
   - Create src/data/skills.ts, export the array, and import it in Skills.tsx.
   Copy from: data/projects.ts
   Learn: export and import, and keeping data separate from UI.

5. Group skills by category
   - Change skills to objects:
       interface Skill {
         name: string
         category: 'Frontend' | 'Backend' | 'Tools'
       }
   - Show a heading per category.
     Hint: skills.filter((s) => s.category === 'Frontend')
   Learn: interfaces, union types and .filter().

6. Add an image to each project
   - Add "image?: string" to the Project interface.
   - In ProjectCard.tsx, show <img> only if it exists.
   Copy from: how "githubUrl &&" works.
   Learn: optional properties and conditional rendering.


LEVEL 3: NEW COMPONENTS AND PROPS
---------------------------------

7. Create an "Experience" or "Education" section
   - Create features/experience/Experience.tsx, plus ExperienceItem.tsx for
     each job or school, plus data/experience.ts.
   - Add it to App.tsx and add a link in Navbar.tsx.
   Copy from: Projects.tsx + ProjectCard.tsx + projects.ts.
   This is the same pattern again, done by you.
   Learn: the full "data -> list -> card" pattern you'll use everywhere.

8. Build a reusable <Section> component
   - Every section repeats <section id="..." className="section"><h2>...</h2>.
     Make one component:
       interface SectionProps {
         id: string
         title: string
         children: React.ReactNode
       }
   - Then use: <Section id="about" title="About Me">...</Section>
   Learn: the "children" prop and removing repeated code.


LEVEL 4: STATE (making things interactive)
------------------------------------------

9. "Show more" button on project descriptions
   - In ProjectCard.tsx:
       const [expanded, setExpanded] = useState(false)
   - Show the full text or a shortened version depending on "expanded".
   Copy from: Contact.tsx (useState, the ternary ? :).
   Learn: each card has its OWN separate state.

10. Filter projects by technology
   - Add buttons (All, React, Node.js...) above the grid in Projects.tsx.
   - Use:
       const [selected, setSelected] = useState('All')
     and projects.filter(...)
   Learn: state that changes what a list shows.

11. Dark/light mode toggle
   - A button in the Navbar with useState<'light' | 'dark'>.
   - Set document.documentElement.dataset.theme = theme
     and add [data-theme="dark"] styles in the CSS.
   Learn: union types in state, and connecting React to CSS.

12. Mobile hamburger menu
   - const [isOpen, setIsOpen] = useState(false)
     and toggle it with setIsOpen(!isOpen).
   - Add a CSS class when it's open:
       className={isOpen ? 'navbar__links open' : 'navbar__links'}
   Learn: toggling booleans and dynamic class names.


LEVEL 5: GOING FURTHER
----------------------

13. Form validation in Contact
   - Show an error if the message is shorter than 10 characters before sending.
   - Add: const [error, setError] = useState('')
   Learn: checking data before using it.

14. Character counter on the message box
   - Show {message.length} / 500 under the textarea.
   Learn: state values can be used directly in JSX. It updates as you type, for free.

15. Load your GitHub repos automatically
   - Use useEffect + fetch('https://api.github.com/users/YOUR_NAME/repos').
   - Show a "Loading..." message while it loads, then the list.
   Copy from: services/api.ts (fetch) and Contact.tsx (status states).
   Learn: useEffect, loading data, and loading/error states.


GOOD HABITS TO PRACTICE ALONG THE WAY
-------------------------------------

- Make one small change, then check the browser. Don't write 100 lines before testing.
- Read the red errors. TypeScript errors tell you exactly which line is wrong
  and why. Hover over the red underline in your editor.
- Run "npm run build" and "npm run lint" after each feature to catch mistakes.
- Use console.log(value) to see what a variable contains (open DevTools -> Console).
- One component per file, named the same as the file, starting with a capital letter.
- Use Git: "git init" once, then after each feature:
    git add .
    git commit -m "Add skills filter"
  If you break something, you can always go back.
- Read the official tutorial alongside this: https://react.dev/learn
  Its sections match these levels closely.


RECOMMENDED PATH
----------------

Do 1 -> 3 -> 4 -> 7 -> 9 -> 10. That covers lists, data, props and state,
which is most of everyday React.
